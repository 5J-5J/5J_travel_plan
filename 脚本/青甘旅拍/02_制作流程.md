# 制作流程与交付标准

## 阶段安排

| 阶段 | 产物 | 完成条件 | 当前状态 |
| --- | --- | --- | --- |
| 0 · 建档 | 需求、素材清单、仓库基线、续接记录 | 已知/未知分开，提交范围清楚 | 首版已完成并同步 |
| 1 · 音乐与参考分析 | 音乐结构、能量/节奏标记、具体参考片段笔记 | 客观测量与听感分开，原曲时间码可复核 | 未开始；仅先做源文件基础核验 |
| 2 · 故事开发 | 少量方向比较、选定方向的简介与情绪弧线 | 适配人物、旅行和拍摄条件 | 待需求补充 |
| 3 · 声音与结构 | 故事节拍表、音乐剪辑/混音方案 | 每一段声音变化都能对应叙事功能 | 待故事开发 |
| 4 · 逐镜脚本 | 景别、双时间线、行动、运镜、声音与转场 | 时间连续，现场可拍，情绪有起伏 | 待前序阶段 |
| 5 · 视觉预演 | 核心镜头参考图、镜号与生成提示词 | 人物/服装/物件连续，镜头与脚本一致 | 未开始 |
| 6 · 执行与检查 | 逐日拍摄清单、备选镜头、最终脚本 | 检查节奏、空间连续性和制作负担 | 未开始 |

在可逆且已有授权的范围内持续推进。只有会实质改变故事的缺失信息才需要继续询问；不得把工作建议默认为用户已确认的偏好。

## 双时间线约定

- **成片时间线**：从成片第一帧开始计时。草案使用 `mm:ss.mmm`，确定项目帧率后可改为 `HH:MM:SS:FF`。
- **原曲时间线**：相对于原始 MP3 解码后的音频起点，标明具体源文件。MP3 编码延迟及不同软件解码结果可能影响精确帧位，最终由剪辑软件中的源文件复核。
- **时间区间**：入点包含，出点不包含；镜头时长等于出点减入点。
- **叠化/声音重叠**：注明重叠时长和所在轨道，不能简单累加片段长度当作总片长。
- **混音片段 ID**：采用 `M01` 等编号，分镜通过 ID 关联源音频区间，避免一镜跨多个音乐片段时混淆。
- **分镜 ID**：采用 `S001` 等固定编号；后续插镜可加后缀，便于图像、清单和修改记录对应。

## 逐镜脚本字段

| 字段 | 写法要求 |
| --- | --- |
| 镜号 | 唯一且稳定，如 S001 |
| 成片入点 / 出点 / 时长 | 明确时间单位和基准 |
| 场景 / 拍摄条件 | 地点、时段、光线；未核实信息加标签 |
| 景别 | 大远景、远景、全景、中景、近景、特写、大特写等 |
| 构图 / 画面 / 人物行动 | 描述摄影者可以实际执行和观察的内容 |
| 运镜 / 焦段建议 / 速度 | 静态或运动方式；器材未定时不硬性指定 |
| 叙事作用 / 情绪变化 | 该镜头新增什么信息，如何改变观众感受 |
| 音乐对应 | M 编号及原曲参考点，是否踩拍或刻意延迟 |
| 同期声 / 音效 / 旁白 | 区分现场录音、后期音效和台词 |
| 转场 / 连续性 | 前后动作、视线、方向、形状或声音连接 |
| 执行优先级 / 替代镜头 | 必拍、可选；器材/天气/时间不足时怎么拍 |
| 参考图 | 对应已保存的本地参考图及提示词 |

## 音乐分析的证据分级

1. **源文件客观信息**：文件大小、哈希、标签、帧头、编码采样率、估算时长。
2. **信号分析**：波形、响度/能量、瞬态、候选节拍；这些数据不能独立证明“悲伤”“释然”等情绪。
3. **试听记录**：明确记录试听是否完成、依据和不确定点；不得把文件名、波形或网上评论描述成自己已听到的内容。
4. **创作判断**：基于以上证据提出的故事情绪和剪辑选择，注明属于建议。

没有完成音乐分析前，不编造 BPM、歌词、高潮位置或看似精确的音乐卡点。

## 文件组织与版本

- 根目录 `bgm/` 保存用户原始音乐，保持不覆盖。
- 本目录保存项目需求、决策、音乐方案、故事、分镜及交付记录。
- `assets/` 后续保存采用的生图参考画面，`prompts/` 保存提示词。
- `analysis/` 保存可复现的素材信息和分析结果。
- `tools/` 保存本项目使用的小型分析工具。
- `tmp/` 仅保存可以重新生成的临时内容，不纳入版本控制。
- 需求、故事与分镜可以迭代；用 Git 提交和 CHANGELOG 记录版本，避免只留下“最终版2”等含混文件名。
